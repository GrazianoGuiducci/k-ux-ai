# K-UX-AI product source

Use [BOOT.md](BOOT.md) to enter the selected work, [KERNEL.md](KERNEL.md)
for the semantic relation, and [CURRENT_STATE.md](CURRENT_STATE.md) for
current product identity. [KERNEL_MANIFEST.json](KERNEL_MANIFEST.json)
locates the native competence, guide and receiving entry.

K-UX-AI is a complex competence kernel: it understands what and how to
make work perceivable and operable, builds original code and learns through
use. Let the knowledge, reasons and experience in
[the competence](competences/ux-ai/COMPETENCE.md) and
[its guide](competences/ux-ai/GUIDE.md) shape the question, composition,
implementation and correction. Runtime modules are available means.

The [Manifesto](MANIFESTO.md) carries the open horizon. Preserve emergent
determinations and let a material difference change the method, code and
dependent projections. A component or example is a situated incarnation;
the competence field remains open.

This repository contains the public product and selected assembled updates
from the producer's formation source. The public methods must remain usable
without access to private development repositories. Keep receiving-kernel
data, credentials and operator-specific context with the receiving owner.
Examples use synthetic data and preserve their illustrative identity.

Use the receiving core's context, competence composition, persistence and
controllers. The LLM entry adapts access to the same semantic owner.
Sources, effect meaning and authority of the domain remain with that domain.

Keep reusable knowledge with the competence that must act differently and
connect it to the receiving environment's live reentry margin. Preserve
concurrent work and local learning when an upstream update arrives.

The executable contract remains in [docs/interface.md](docs/interface.md).
A source change, package publication, website deployment and connection
to a real domain controller have distinct identities and effects.
